## Prerequisites

1. macOS с выбранным Xcode, iOS Simulator runtime и физический iPhone с iOS 17+
   для камеры/фото/Apple Sign-In. Проверка камер — на младшем и старшем поддерживаемом устройстве.
2. Docker + Supabase CLI для локальной изолированной базы, Deno для серверных tests.
   Версии закрепить вместе с SDK lockfiles при создании scaffold.
3. Apple Developer App ID/capabilities и Google OAuth clients для приложения;
   Supabase providers и anonymous auth. Эти аккаунты здесь не создавались.
4. App Store Connect subscription group и два продукта польского магазина:
   месяц 49,99 zł без trial, год 199,99 zł с 7-дневным trial для eligible пользователей.
   Нужны eligible/ineligible Sandbox testers, Apple API credentials и root certificates.
   Квартального продукта в MVP нет. Локальная StoreKit configuration отделена от production;
   ускоренное время Sandbox фиксируется в отчёте, а не принимается за семь реальных суток.
5. Server secrets: Anthropic API key, Apple key/issuer/app identifiers, privileged
   Supabase credentials и защищённые provider revocation credentials.
   В iOS bundle допустимы URL проекта и publishable key, но не service-role/AI/Apple private keys.
6. Партии подтверждённых фактов ухода и отдельный выпуск протоколов проблем по SC-016, права доноров/credits и Golden Records PL/EN;
   отдельная заранее размеченная eval-выборка без неразрешённых фото.

## Локальная среда после реализации scaffold

Из корня проекта, только для локальных тестовых данных:

```sh
supabase start
supabase db reset
supabase test db
supabase functions serve --env-file supabase/.env.local
```

Локальный `.env.local` создаётся при реализации и исключается из Git; значения
секретов не выводятся в отчёты. Нельзя подменять локальный fixture production key.
Database tests должны включать RLS и транзакционные команды ухода.

Отдельный терминал:

```sh
deno check --config supabase/functions/deno.json supabase/functions/plants-api/index.ts
deno test --allow-env --allow-net=127.0.0.1,localhost supabase/functions/
```

Обычные tests используют fixtures и локальные сервисы, не платного провайдера.
Совместимость Apple SignedDataVerifier проверяется дополнительно в точном Edge Runtime:
валидная и неверная цепочки, OCSP/network, JWS application identifiers и App Store API auth.
Успешная сборка TypeScript без этих проверок не закрывает G02.

## Сборка и UI tests после создания проекта

Сначала определить доступную destination:

```sh
xcodebuild -project ios/Plants.xcodeproj -scheme Plants -showdestinations
```

Задать `PLANTS_SIMULATOR_UDID` действительным ID из вывода, затем выполнить оба языка:

```sh
xcodebuild -project ios/Plants.xcodeproj -scheme Plants -destination "platform=iOS Simulator,id=${PLANTS_SIMULATOR_UDID}" -testLanguage pl -testRegion PL test
xcodebuild -project ios/Plants.xcodeproj -scheme Plants -destination "platform=iOS Simulator,id=${PLANTS_SIMULATOR_UDID}" -testLanguage en -testRegion PL test
```

Схема Plants должна содержать unit/UI test targets и локальную StoreKit configuration
для тестового режима. Учебные покупки/fixture entitlements не дают production доступ.
Native Apple/Google sign-in и camera hint дополнительно проверяются на реальном устройстве.

## Приёмочные маршруты

Каждый маршрут выполняется PL/EN. Отчёт фиксирует build, locale, environment, регион
магазина, начальные Free/Trial/Paid и квоты, дату/часовой пояс, действия и фактический исход.
Для billing записываются eligibility, подтверждённые даты доступа и запланированное списание;
секреты и полные платёжные документы в публичный отчёт не попадают.
Названия технических команд ниже — ориентиры существующего проекта, требующие сверки после
обновления контрактов; ожидаемое поведение определяется текущей спецификацией.

Термин **trial** означает только семидневный подписочный период; бесплатные фотоанализы
называются **стартовыми попытками**. Управляемые часы используются для месячных границ,
trial, просрочки и отчётов; ждать календарный месяц или выполнять платные AI-вызовы не нужно.

## Reference-based eval и производительность без обязательного специалиста

1. Зафиксировать cases и expected labels до ответов модели: общая выборка минимум
   200 случаев; минимум 100 определимых видов и 100 причин могут пересекаться.
   Включить healthy, ошибки ухода, вредителей, болезни, плохие фото и not-plant.
   Метки/допустимые действия фиксировать по независимым источникам до запуска;
   оцениваемая/синтезирующая LLM не размечает себе приёмку. Специалист не обязателен.
   Результат — соответствие reference cases, не экспертно подтверждённая точность.
2. Прогнать выбранную Haiku 5.5 отдельно PL/EN с одинаковыми фото/условиями.
   Сравнить medium/low effort и 1568/2576 px, измеряя фактический usage и latency.
3. Для каждого ответа сохранить model ID, prompt/schema/catalog version, locale,
   image variant, stop_reason, reference labels / protocol match scores и причину ошибки. Не сохранять внутренние
   рассуждения, секреты и подписанные media URLs в отчёт.
4. Посчитать species top-1, основную причину, первое действие и явную неопределённость
   по SC-003/004. Abstention на определимом случае не засчитывать как успех.
5. Отдельно измерить минимум 100 запусков на каждом языке по SC-002; failures входят
   в denominator. Учитывать загрузку фото, очередь и обработку, а не только время модели.
6. Подтвердить SC-001/007/012/013 на минимум 20 участниках каждого языка.
   Для SC-012 >=90% правильно выбирают оба пути; >=90% вошедших сохраняют известный вид
   без фото/комнаты <=90с от добавления. Для SC-013 >=90% называют первое действие и его
   основание, после полного плана — срок проверки и сравниваемый признак по заранее заданной рубрике.
   SC-014 проверяется функциональными сценариями и различением manual/camera_estimate/unknown.
   Редакторы PL/EN проверяют UI, ошибки, push-тексты и AI-ответы.
7. Выпуск не проходит при недостаточном качестве/времени; корректировать параметры,
   данные и prompt в рамках выбранной модели, затем повторить затронутые проверки.

Запуски, использующие живой AI/API и Sandbox accounts, выполняются на соответствующем
этапе реализации с настроенными credentials и расходным лимитом. Здесь таких запусков не было.
