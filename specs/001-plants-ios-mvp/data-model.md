# Минимальная модель данных Narat

Цель от 2026-11-09; [spec](spec.md), [переход](contracts/revision-2026-11-09.md). Существующие SQL/JSON Schema ещё требуют T155/T157–T160. Таблица ниже описывает необходимые данные, а не требование переписать работающие таблицы.

| Область | Необходимые данные и ограничения |
| --- | --- |
| Вид и каталог | Стабильный taxon ID, научное/EN/PL имена и синонимы, описание/справочное фото с правами, версия выпуска. Личный экземпляр имеет другой ID. Каталог публикуется без полной KB. |
| Проверенный факт/действие | ID, применимый вид/проблема/условия, значение/единица при необходимости, действие и основание EN/PL, источник/основание использования/проверка, версия. Unknown и конфликт не разрешают совет. |
| Выпуск KB | Версия, перечень фактов/действий, manifest/hash, проверка и published state. Один текущий выпуск, сохранность ссылок старых результатов. Не требуются полный профиль, универсальные словари/редакторский workflow или минимальное покрытие. |
| Профиль | Owner, active/deleting state, язык, час reminders, immutable registered_at, verified entitlement и различимый факт остановки автоматического ухода после expiry. Новый Free отличается от бывшего подписчика. |
| Экземпляр | ID/owner, имя, nullable taxon, личное фото при наличии, известные условия/unknown. Плоская коллекция; старые room IDs можно сохранить для истории, без CRUD в MVP. |
| Фото и контекст | Приватный photo asset, дата снимка/загрузки, owner/экземпляр; неизменяемый исходный контекст анализа. Правка вида/условий не переписывает прежний результат. |
| Гостевой черновик | Source owner, succeeded_at, expires_at=success+7 суток, фото/ответы/результат. Действительный claim с proof защищён от cleanup; удалённый draft не восстанавливается из локального результата. |
| Analysis job/result | `identification`/`diagnosis`, owner/photo/locale/context, версия каталога/KB, quota reserve/period/lease, классификация/ограничения, IDs и snapshot применимых рекомендаций. Без AI-follow_up, diagnostic answers/score routing. |
| Рекомендации | Snapshot действий сейчас, основания/применимости и следующей проверки. Current/paused/superseded для сохранности актуальности, без лечебных стадий. Чтение истории разрешено после expiry; расширенное обновление требует paid. |
| Проверка/журнал | Task связан с действием/правилом и следующей датой, если она обоснована. Record/reversal сохраняют фактическую местную дату и время внесения. Первая помощь имеет не более одного связанного контроля; обычная проверка повторяется по проверенному правилу. |
| Billing/квоты | Purchase ownership/verified events, два starter, месячные Free/paid ledger с общим anchor регистрации, reserve/consumed. Дневной бюджет провайдера отдельно от пользовательской квоты. |
| События | Минимальный enum, event_id, время и owner scope; client best-effort, purchase server-only. Нет report cache и второй постоянной очереди аналитики. |

## Сохранность и синхронизация

UUID для экземпляров/операций, стабильные semantic IDs для KB; UTC timestamps и местная DATE+timezone для фактического ухода. Owner/RLS обязательны. operation_id с hash payload даёт один результат; один ID с другим содержимым — conflict. Care-команда не отклоняется только из-за старой revision, пока растение существует.

Существующие updated_at/deleted_at, монотонный owner watermark, receipts и устойчивую пагинацию сохраняем. Порядок locks: profiles по UUID → installation_access → monthly_quotas → plants → дочерние записи; сеть вне транзакционных locks. Удаление оставляет tombstone до удаления аккаунта; очистка файлов отдельно. care_revision меняется при виде/условиях, а не имени/фото.

В транзакции ухода пересчитывается только применимое будущее. Поздняя запись не перекрывает более поздний фактический уход. Paused/expired не создают следующих задач; ручной журнал не снимает паузу. У текущей даты есть короткое основание, отдельная таблица пользовательского журнала пересчётов не нужна.

## Что не переносить в новый активный контракт

Комнаты/выбор главного фото, AI-follow_up, лечебные timeline/repeat-count цепочки, diagnostic questions/decisions, camera estimate, Free-места, report, товарные SKU/таймеры/blocks, expired-guest fallback. Историческое хранение не равно активной поддержке. Неизвестные старые данные не конвертировать в подтверждённые факты. Точные удаления/адаптеры и upgrade проходят отдельные проверки T157–T160.
