# Компактные карточки v2 — технический переход T157

Формат реализует принятые действия сейчас и следующую проверку; это не новая продуктовая программа. Миграции пользовательских результатов и автоматическая конвертация старых рекомендаций не нужны.

ConditionProfile v2: schema_version=2.0, kb_release_id/record_version, provenance, condition_id, host_scope, visual_markers, противопоказания, title/summary EN/PL, first_help_action_id и actions. Убраны category/abiotic priority, обязательные диагностические проверки, treatment_plan, длительность/стадии/порядок/повторы, comparison/photo-angle descriptors.

Действие: action_id, action_code, purpose, action_en/pl, prerequisite_check_ids, contraindication_check_ids, next_check_interval_days (проверенное 1..90 дней либо null), необязательные active_ingredients. Число 90 сохраняет прежнюю техническую границу, не назначает универсального срока. Нет фиксированного числа действий или лечебной последовательности. Основание — summary карточки/наблюдения и provenance. Вещество не заменяет проверку применимости/условий; дозы/способ не генерируются.

Resolver выбирает ровно first_help_action_id для одного опубликованного применимого кандидата. Не выбирает произвольный первый action, не выводит пригодность из scores. Неизвестные prerequisites не считаются выполненными; ранее принятые host/contra/unknown safeguards сохраняются. Null интервала означает отсутствие автоматического срока, запись ухода и здоровье из него не выводятся.

PlantProfile v2: schema_version=2.0, release/version/provenance, plant_id (связь с отдельным каталогом), actions в том же формате и optional safety. Можно публиковать одно действие без света/грунта/подкормки либо независимый safety факт при пустом actions. Полностью пустая карточка без safety отвергается; safety-only не означает готовность расписания. Нет обязательных taxonomy/полного care_algorithm_params/рецепта/модификаторов/месяцев подкормки. Непоказанные safety данные остаются неизвестными.

Происхождение/права/field evidence/ручная проверка сохраняются из принятого source-среза. Старые v1 schemas копируются побайтово в legacy/ как технические снимки после предыдущей очистки. Они не используются для нового runtime; исторические сырые результаты/планы/подписи не переписываются и не валидируются заново как v2. Старый профиль не может молча стать новой применимой рекомендацией. Точные schemas задаются независимым t157_compact_profile_gate.py; готовность сценария принимается отдельно.
