# Переход к простому MVP — 9 ноября 2026

Основание — [решение владельца](../../../docs/validation/spec-simplification-2026-11-09.md). При противоречии эта редакция и актуальный spec заменяют редакцию 8 ноября. Правила месячных периодов, starter, guest семь суток, collection cap и expiry из неё остаются.

| Срез | Изменение | Обязательная проверка |
| --- | --- | --- |
| T157 — анализ/KB | Identification/diagnosis; повторное фото — diagnosis. Убрать follow_up/questions/decision scores и обязательный полный профиль. Компактные проверенные действия вместо timeline. Schema/TS validator/resolver/Swift DTO/fixtures согласованы одним переходом. | Unknown/invalid IDs, EN/PL, старая история, отсутствие второго AI/порогового опроса; тесты целевого контракта и live provider отдельно. |
| T158 — коллекция/доступ | Убрать room CRUD/Free slots и старые проекции; сохранить данные, атомарный count<3 и истечение ухода. Уход доступен на новом Free, бывший paid после expiry остановлен. | Clean/upgrade, два владельца, quota расход/даты, одновременное добавление, retry, история/room данные не потеряны. |
| T159 — guest/вторичные механизмы | Убрать deleted-draft fallback, report DTO/cache/claims, товарные SKU/timer/blocks, server trial claim. Проверить всех consumers analysis_receipt: убрать подпись лишь если безопасный server result+claim proof полностью покрывает перенос. Operation receipts остаются. | Claim до/на границе/после срока, copy/cleanup race, сохранность media; старые команды отвергаются, нет ложного успеха; локальный trial reminder и billing не зависят от удалённого claim. |
| T160 — уход | Простые действия/следующая проверка, один контроль первой помощи, обычный повтор по правилу; без лечебных стадий/сезонного override UI/истории пересчётов. Убрать специальные photo export/main/comparison flows. | Record/undo/backdate/offline/restart, cancellation of first-aid control, no duplicates, known expiry offline, applicability pause/update, photos/history preserved. |

T155 закрывается только после четырёх срезов и проверки совместимости; T156 закрывает лишь принятие модели в документах. Подчинённые изменения должны интегрироваться с соответствующими продуктовыми задачами. Не объявлять срез готовым одним build или набором fixtures.

Старые применённые миграции не менять. Для текущего стенда нужны forward migrations и тесты upgrade, включая перенос расхода без выдачи новой квоты. Ненужные поля сначала исключить из активных writers/projections; физическое удаление лишь после проверки потребителей/данных. Старые результаты/фото/история остаются читаемыми. Точная текущая vs целевая machine schema документируется при реализации, а не считается совпавшей из-за новой Markdown-версии.

Целевые события: method_selected, analysis_succeeded, analysis_failed, plant_saved, care_recorded, paywall_shown, purchase_confirmed. `intent_selected` в старом контракте заменяется method_selected (check/identify/catalogue), не требуя экрана выбора намерений. Client best-effort, server event_id dedup; purchase server-only. Запрещены приватные payload. События не являются источником квоты/entitlement.
