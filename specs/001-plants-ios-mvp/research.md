# Технические решения Narat

Актуализация 2026-11-09 по [принятому упрощению](../../docs/validation/spec-simplification-2026-11-09.md). Это обоснование архитектуры, не новые внешние исследования или проверка SDK.

| Решение | Причина и граница |
| --- | --- |
| Сохранить SwiftUI/SwiftData, Supabase, StoreKit 2 и согласованную модель | Смена технологий не нужна для сокращения scope; реальные интеграции проверяются отдельно. |
| Два режима analysis: identification / diagnosis | Основная диагностика уже включает вид; отдельная AI-динамика не нужна для повторного фото. |
| Источник рекомендаций — проверенные карточки | Короткая рекомендация не требует генерации новых советов; ручная подготовка достаточна для первой партии. |
| Один простой формат ухода | Действия и следующая проверка покрывают основной путь без универсального лечебного движка. |
| Сохранить existing sync/outbox/receipts | Уже существующий фундамент защищает действия. Полная замена не имеет подтверждённой выгоды; удалить только лишние проекции. |
| Сохранить job/lease/quota/budget и server billing | Это границы подтверждённых результатов/расхода/доступа, а не необязательные экраны. |
| Guest claim остаётся, local fallback снимается | Семидневный результат существует на сервере; proof нужен для безопасного переноса между владельцами. Нужность отдельного analysis_receipt проверяется в T159, не путать с operation receipt. |
| Локальные trial reminders | Один добровольный reminder на устройство; распределённая гарантия единственной доставки не нужна. |
| Best-effort клиентские события | Нет необходимости второй надёжной очереди; billing и бюджет не зависят от аналитики. |
| Разделить ранние прогоны и публичный eval | Убрать фиксированные объёмы как универсальный gate, сохранив заранее определённые выборку, цели и проверку опасных ошибок. |

Точные технические инварианты — [API](contracts/api.md), [sync](contracts/sync.md), [модель](data-model.md). Исторические исследования источников в `research/plant-data/` и `docs/plant-database-sourcing.md` сохраняют доказательства и ограничения, но не расширяют MVP автоматически.
