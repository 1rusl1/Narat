## Правила приёмки и порядок

- Отметка `[X]` означает прежнюю приёмку неизменённого объёма, а не новую проверку в этом документальном этапе. Изменённые ранее закрытые задачи переоткрыты; готовые компоненты и исторические доказательства не удаляются.
- T148 остаётся текущим незавершённым этапом данных; затем T149. Её импорт/редактура не ждут полной лечебной базы. Перед интеграцией затронутого API/SQL/клиента — T155 и соответствующие foundation/contract задачи.
- T149: действительный каталог → вход → сохранение → чтение/retry/restart/owner isolation с новым лимитом коллекции. T150 требует T153 для независимого identification; T151 принимает оба пути.
- Уход по применимым фактам и фактическая история сохраняют исходную ценность. Снятые функции не возвращать из прежних схем, тестов или комментариев. Код и развёрнутый стенд ещё не приведены к новым требованиям.
- Для существующего стенда добавлять forward migrations и проверять upgrade; не переписывать применённую миграцию ради чистой установки. История/фото/расход квот сохраняются.
- T156 отложена владельцем. Все пометки OPEN-PLAN запрещают автоматическое завершение соответствующего объёма по старой схеме; независимую часть задачи можно делать, но всю задачу не закрывать.
- `[P]` разрешает параллельное выполнение только при готовых зависимостях и разных изменяемых файлах. Проверки разделяют fixtures, реальные интеграции и приёмку пользовательского сценария.
