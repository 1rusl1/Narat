## Разрывы перед следующим этапом

1. Default `/commands` возвращает `committed` без записи в БД; `/sync` возвращает пустую страницу. При подключении клиента это может привести к снятию неподтверждённой операции из outbox. Нужны реальные адаптеры и проверки подтверждения/повтора.
2. API установки/access/media/jobs требует внедрённых adapters, но рабочий entrypoint их не создаёт. Claims/catalogue/basic care в основной router не подключены. Worker entrypoint отвечает только `analysis-worker-ready`.
3. Клиентский `AnalysisFlowModel.submitAnalysis` создаёт фиксированный результат Monstera/overwatering, локально списывает квоту и использует строку `signed_receipt_v3`. Это не реальный серверный анализ или подписанная квитанция; не передавать такую заглушку как доверенный результат в claim/fallback.
4. Третий вопрос клиента — дата последнего полива, а спецификация требует дренаж. Исправить связанный контракт/модели/экран/тесты.
5. Claim DTO клиента, обработчика и API-контракт расходятся по полям и proof. Их необходимо согласовать перед реализацией T046, а не закреплять расхождение новым клиентом.
6. CI пока выполняет iOS `build-for-testing`, без запуска UI/unit, SQL и отдельной проверки PL/EN. Новая концепция дизайна пока не перенесена в SwiftUI.

Это выявленные проблемы, а не выполненные исправления. В рамках обзора код и отметки задач не изменялись.
