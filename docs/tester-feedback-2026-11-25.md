# Исправления после первого ручного обзора —25ноября2026

База: код/отчёты a6d03c3, техническая сборка0.1.0(4). Её fixture/representative PASS не подтверждает первый нативный OAuth-вход. Главная композиция Quiet Garden сохраняется. Поиск, покупки и расширение рекомендаций отложены. Это целевая проверка маршрутов, не повтор всего T099.

## A. Первый вход и сохранение — T046/T049/T097/T098

Из fresh guest открыть список каталога, выбрать вид, ввести имя, Save→понятный вход/создание аккаунта существующими провайдерами→сохранить ровно одну карточку→открыть после cold launch. Повторить путь из фото с тем же изображением. Доступность провайдера соответствует конфигурации текущей ordinary signed сборки. Cancel/error/retry видимы; поля/вид/photo/checkpoint/operation не теряются, точный retry не создаёт второй экземпляр. Email-регистрацию в продукт автоматически не добавлять. Для следующей проверки нужен отдельный тестовый вход: credentials только в защищённом локальном файле, без Git/чата/логов.

В выданных Personal и Simulator Google client/server IDs и callback отсутствуют; CatalogueSaveView рисует Google без проверки. Это config/UI inconsistency, не установленная native root cause. Владелец подтвердил отсутствие Google-конфигурации и только Simulator сейчас. Подготовить точную инструкцию владельцу; positive liveGoogle/physical оставить OPEN до конфигурации/доступа.

## B. Прямые входы и навигация — T170/T096

Check проверяет состояние, Identify определяет вид. Прямой вход не требует How would you like to add your plant for care. Верхний native Back возвращает предсказуемо; Opening/loader заметен вверху/центре. У каждого режима отдельный starter; 0/1 и1/1 могут быть правильными по FR-065. Объяснить текущий режим/остаток/следующий шаг при исчерпании; не объединять квоты/не обещать бесплатный повтор unknown. Старый intent/retry не подменяет новый режим.

## C. Каталог и изображения — T046/T047/T096/T175

Fresh Browse открывает список, не прошлую карточку. Незавершённый save можно явно продолжить без потери durable checkpoint/полей; не очищать его молча. Понятное действие изменения нового сохранения отделить от exact retry, убрать Edit as a new save из обычного UI. Миниатюры — отдельная T175, выше поиска. Использовать только опубликованный listDTO hero_image с атрибуцией и missing/loading/error placeholder, без N+1 details/массовой загрузки606/подмены личного фото.

## D. Предложение вида и ручная коррекция — T047/T150/T170

Предполагаемый вид показать карточкой: картинка-пример, название и проверенная опубликованная базовая информация, явная неопределённость, Confirm и Choose another species. Unknown сразу предлагает ручной выбор. Сохранить исходное photo/job/flow и возможность вернуться; без нового анализа/upload/квоты ради коррекции. Выбранный ручной вид должен быть опубликован и сохраняться с исходным личным фото ровно один раз. Late responses/Back/signout/new photo не подменяют текущий выбор.

Текущий showCatalogue вызывает cancelAnalysis и очищает job/photo provenance; unknown не сохраняет identifiedPhoto без AI-species. Эти переходы нужно исправить без изменения server idempotency/owner/expiry. Числовой confidence threshold в проверенном identification-контракте не найден: его не объявлять причиной. Качество конкретного Monstera-ответа проверяется только при наличии оригинала/метки; иначе записать ограничение и использовать разрешённую размеченную выборку, не self-labeling.

## Выполнение и доказательства

Два изолированных iOS-кандидата через существующий Developer/Reviewer/QA workflow: AUTH→catalogue; независимый direct navigation→identification. Пересекающиеся App/Guest-файлы не редактируются в одном checkout. Root объединяет принятые срезы между runs; Xcode/Simulator только под общим resource lease/раздельными DerivedData. Source/model tests и targeted UI по каждому срезу, затем регрессия объединённого исходника, обычная signed Simulator-сборка и просмотр нужных экранов. Не запускать большой набор заново для каждой строки/не считать build доказательством пользовательского сценария.

Fixtures, обычная сборка с живым backend, Google/Apple OAuth и физический iPhone имеют отдельные статусы. Новый артефакт/номер, sourcecommit, подпись/UUID, ограничения, handoff и push фиксируются по факту. Три пользовательских PBX/xcstrings не перезаписываются/не попадают в stage.
