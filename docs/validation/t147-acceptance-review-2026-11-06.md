# Проверка готовности T147, 6 ноября 2026

Четыре замечания от 5 ноября закрыты. Две дополнительные пробы на свежей PostgreSQL 17.11 воспроизвели потерю видимости опубликованной карточки. T147 повторно открыта. Редакционная приёмка T148 может продолжаться. T149 зависит от T147 и T148.

## P1. Роль anon может изменить каталог через триггер

В миграции `202611050001_catalogue_skeleton.sql` функция `activate_catalogue_release_snapshot()` объявлена с правами владельца (строка 572). В списке REVOKE на строках 932–936 она отсутствует. Функция доверяет полям переданной строки, не проверяя таблицу-источник.

В локальной БД опубликованы последовательно v1 и v2 с одним общим видом. До проверки поиск возвращал 1 и карточку v2. Для роли `anon` проверены права EXECUTE на функцию и TEMP на базу. Оба значения — true. Под этой ролью выполнены следующие команды, где `<v1>` — известный UUID ранее опубликованного релиза.

```sql
SET ROLE anon;
CREATE TEMP TABLE shadow_release(id uuid, version text, state text);
CREATE TRIGGER forged AFTER INSERT ON shadow_release
  FOR EACH ROW EXECUTE FUNCTION public.activate_catalogue_release_snapshot();
INSERT INTO shadow_release VALUES ('<v1>', 'v1', 'published');
```

Активным остался v2, но строка вида получила release_id от v1. Публичный поиск вернул 0, карточка стала NULL. Для воспроизведения требуются возможность исполнять SQL от роли с TEMP и известный UUID снимка. Доступность такого пути через удалённый HTTP API остаётся непроверенной.

Отозвать EXECUTE на функцию у PUBLIC и клиентских ролей, привязать вызов к исходной таблице проверкой TG_RELID и добавить отрицательный тест установки поддельного триггера. Проверить, что штатная активация по-прежнему работает.

## P2. Переключение через status пропускает активацию снимка

В отдельной проверке сначала восстановлен v1 штатной функцией публикации. Затем доверенная роль последовательно выполнила `UPDATE catalogue_releases SET status='retired' WHERE id=<v1>` и `UPDATE catalogue_releases SET status='published' WHERE id=<v2>`. Синхронизатор скопировал status в state (`202610200002_catalogue.sql`, строка 72). Триггер активации подписан на `UPDATE OF state` (`202611050001_catalogue_skeleton.sql`, строка 619), поэтому оба UPDATE прошли без материализации снимка. В БД v2 опубликован, поиск вернул 0, карточка стала NULL.

Активировать снимок по фактической смене состояния при изменении любого из двух полей либо явно отклонять обновление через status. Добавить тест на оба направления переключения.
