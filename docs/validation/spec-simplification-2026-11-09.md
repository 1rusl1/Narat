## Зафиксированные детали простого ухода

- Рекомендация содержит действие, основание, применимость и условие следующей проверки. Дата есть только при проверенном правиле и известной точке отсчёта.
- Включение ухода не является фактом выполнения. Повтор обычной проверки требует применимого правила и активного доступа; первая помощь имеет один связанный контроль при наличии данных.
- Отмена/исправление не создаёт дубль контроля; отмена исходной первой помощи снимает её незавершённый контроль. Завершение действия не доказывает выздоровление.
- После правки вида/условий неподходящее будущее ставится на паузу. Явное обновление из базы заменяет будущее, сохраняя старый результат/историю; неподтверждённые данные не позволяют продолжение.
- Если лечение требует неподдерживаемой последовательности, MVP показывает ограничение и пригодную первую помощь, не выдаёт опасно сокращённое лечение.
- Free остаётся первой помощью/контролем и базовым уходом; paid — дополнительные применимые действия, обновления, 100 анализов и отсутствие лимита добавления. Обещание многоэтапной программы снято.

## Граница применения

Этот этап согласует спецификацию, конституцию, план/задачи, текстовые контракты, дизайн/ASO и инструкции. Машинные JSON Schema и runtime SQL/Swift/TypeScript имеют отдельный переход T155/T157–T160; старый код не объявляется соответствующим новым документам. Один локальный gate каталога исправляется отдельно и проверяется на фактическом выпуске. Старые графические ASO-артефакты выводятся из активного использования до новой генерации и визуальной проверки.

T156 можно закрыть после проверки документационного формата/согласованности. Другие продуктовые задачи не закрываются из-за изменения текста. Точные проверки, число задач, ограничения и отправка Git — в [handoff](../handoff_status.md).
