## Разрывы, которые необходимо устранить

1. **Сервер подтверждает несохранённые команды.** В `supabase/functions/plants-api/index.ts` default `/commands` отвечает `status: committed` без вызова БД, а default `/sync` отдаёт пустую страницу. Реализация `SyncEngine` может считать такой ответ подтверждением и снять операцию из очереди. До подключения к реальным пользовательским данным заменить заглушки рабочими адаптерами; тестом проверить запись в БД и повтор после потери ответа.
2. **Часть API доступна только через внедрённые тестовые зависимости.** Маршруты установки, доступа, загрузки и analysis jobs требуют `deps.*Adapter`; entrypoint вызывает `createPlantsApiHandler()` без этих адаптеров. Claims/catalogue/basic care не подключены к этому роутеру. Наличие соответствующих `.ts` не означает доступность endpoint.
3. **Worker entrypoint не обрабатывает задания.** У `analysis-worker/index.ts` есть функция обработки с внедряемыми зависимостями, но `Deno.serve` в точке входа возвращает только `analysis-worker-ready`. Нужны рабочие persistence/budget adapters и запуск обработки/восстановления очереди.
4. **Результат в приложении локальный и демонстрационный.** `AnalysisFlowModel.submitAnalysis` сам создаёт Monstera/overwatering, меняет локальный счётчик и присваивает `signed_receipt_v3`. Это не серверная квитанция. Нет подтверждённой связи фото → upload → job → worker → result → кеш/сохранение. Константные рекомендации и сроки не должны выдавать себя за результат проверенного протокола.
5. **Вопросы расходятся со спецификацией.** Третий вопрос `CareQuestionsView` — время последнего полива, а FR-004 и Session 2026-10-30 требуют наличие дренажных отверстий. Исправление должно пройти через DTO, серверные поля, интерфейс и тесты, не только через подпись кнопки.
6. **T041 ещё не подключена к пользовательскому сохранению.** Сервис готов, но `CollectionRepository`, `ClaimFlowModel` и экраны коллекции ещё отсутствуют. До native sign-in нужно сохранить исходный результат/квитанцию и получить proof; после подтверждения переноса очистить кеш. Живые OAuth-параметры и device sign-in не проверены.
7. **Клиент/сервер claim требуют согласования.** Например, `ClaimOverridesDTO` использует `taxon_id`/`new_room_name`, а `claims.ts` ожидает `species_id`/`create_room_name`; API-контракт описывает proof, текущий commit DTO сервера — другой набор полей. Перед T046 сверить endpoint, SQL, receipt, staging/poll и DTO с `contracts/api.md`; не подстраивать клиент к неподтверждённому протоколу.
8. **CI не подтверждает заявленное покрытие.** Workflow выполняет Deno task и iOS `build-for-testing`. В нём нет запуска `xcodebuild test`, pgTAP и отдельной матрицы PL/EN. Бейдж/успешная сборка не означают прохождение этих проверок.
9. **Нет готового содержимого и приёмки.** Не представлены полный опубликованный release 300 растений/40 проблем, pipeline, размеченный eval и результаты качества/задержки/usability. SQL/RLS/Storage-проверки в данном обзоре не запускались. Docker не найден в текущем PATH; это не доказывает отсутствие всех возможных способов запуска БД.
10. **Новый дизайн пока концепция.** Quiet Garden, отдельные EN/PL промпты и интерактивный эскиз существуют. Текущие SwiftUI-экраны ещё не приведены к этой концепции; три вкладки и полноценная коллекция не реализованы.

5. Затем продолжать по зависимостям: планы/подписки, уход/дневник, напоминания/профиль, уточнения/timeline, отчёты/аналитика и приёмка. Pipeline Golden Records — отдельная обязательная цепочка; без него живые рекомендации не готовы.
