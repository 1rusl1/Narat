## Чего не хватает для функций MVP

### Карточка и поиск

Нужны структурированные family/genus, сверка принятого таксона и научных синонимов, редакционно выбранные EN/PL common names, классификация алиасов и привязка к production taxon/release IDs. Family местами упомянуто в свободном описании, но отдельного проверенного поля нет. Parent QID не подменяет готовое genus/family.

Фото технически скачаны, но `review_status` прямо указывает на незавершённую проверку соответствия виду/пригодности для интерфейса. Одно утверждённое фото может быть достаточным для карточки; дополнительные ракурсы не объявляются обязательным требованием. Текущие изображения — оранжерея/дерево/листья, не утверждённые hero-фото комнатных экземпляров. Фото эпипремнума 15 946 112 bytes требует подготовки app-варианта; для BY-SA сохраняются соответствующие условия и сведения об изменениях.

### Базовый уход и расписание

Отсутствует целиком `care_algorithm_params`: стратегия полива, условие проверки почвы/сухости, сезонные базовые интервалы, применимые модификаторы, min/max интервал проверки, протокол неизвестных условий, требования к свету, субстрат и подкормка. Нет готового routine template.

Часть численных полей схемы допускает null; их не нужно заполнять догадками ради видимой полноты. Нужны проверяемые основания и применимый безопасный протокол, который действительно может использовать ScheduleCalculator. Неизвестный климат/горшок не превращается в выдуманный множитель.

### Safety

Текущие `cat/dog=unknown` — честный статус отсутствия проверенной записи, а не безопасность. Нужен структурированный статус с точным таксоном, источником, областью применимости и причиной unknown; вещество/severity остаются неизвестными при отсутствии основания.

Личная копия ASPCA для монстеры не была преобразована в утверждённый PlantProfile и не опубликована. Для фикуса и эпипремнума соответствующие reference-страницы в пилоте не сохранены. Сам факт скачивания одной страницы не закрывает animal safety для всего набора.

### Диагностика и восстановление

Названий и фото недостаточно для первой помощи/плана. Нужны связанные `common_vulnerabilities`, применимые ConditionProfile, признаки/уточнения, проверенные действия, противопоказания, сроки/признаки контроля и fallback при неопределённости. Эти общие протоколы могут использоваться несколькими видами; создавать 40 отдельных проблем заново для каждого растения не требуется.

### Языки и источники

Нужны EN/PL watering_tip, soil_recipe, light_tip, fertilizing_tip и safety_note из одного проверенного ядра. По KB pipeline полный профиль требует минимум три независимых донора, а рекомендации/числа — минимум два независимых основания с field_evidence; для отдельных authoritative фактов предусмотрены исключения. Wikidata и фотографии Commons не закрывают независимое покрытие ухода.

Нужны source documents/locators/права на соответствующие операции, разбор конфликтов, схема/semantic validation, версия профиля и релиза, reviewed/published status. В пилоте их полного набора нет.
