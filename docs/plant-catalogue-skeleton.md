# Первый этап — базовый каталог растений

Первоначальное решение: 2026-11-04. Актуализация 2026-11-09: фактический каталог сохраняется, минимальный охват и полный профиль не являются gates MVP. Основание: уточнение владельца проекта в чате.

## Цель и границы

Исходный локальный каталог содержит 606 видов. Ближайший результат — поиск, карточка и сохранение растения в iOS. Для обычного ухода к виду постепенно добавляются проверенные факты. Первое обогащение — по какому признаку определить готовность к поливу. Продуктовые критерии приведены в [спецификации](../specs/001-plants-ios-mvp/spec.md); карточки готовятся по [минимальному процессу](../specs/001-plants-ios-mvp/knowledge-base-pipeline.md).

## Фактическое покрытие исходного выпуска

Снимок перенесён из прежнего введения spec: 606 видов с научным названием, фото, EN/PL описаниями и исходными поливочными данными. Обиходные имена: 407 EN и 430 PL. Все четыре сезонных интервала есть у 556 видов, частично — у 49, у одного водного вида все отсутствуют. Сопоставления полива: 278 точных, 16 по синониму, 222 по роду, 90 по группе. Это инвентарь, не приёмка применимости рекомендаций; свежие данные — `catalogue/releases/skeleton-300-v1/coverage.json`.

Первое полезное дополнение — наблюдаемый критерий готовности к поливу для среды. Затем можно независимо добавить свет, субстрат и другие действия по проверенным данным; полного профиля для каждого вида ждать не нужно. Каталожные интервалы/метод сами по себе не подтверждают безопасное расписание экземпляра.

## Состав карточки вида

| Поле | Требование первого этапа |
|---|---|
| Стабильный ID | Связывает вид с экземплярами пользователя и будущими модулями; название не используется как ключ |
| Научное название | Принятое латинское имя, обязательное для опубликованной карточки |
| Распространённые названия | Несколько названий с языком EN/PL; участвуют в поиске. При отсутствии подтверждённого названия показываем научное, перевод не выдумываем |
| Основное изображение | Одно проверенное изображение вида для списка и карточки; источник и атрибуция сохраняются |
| Общее описание | Короткий текст о внешнем виде и особенностях растения на EN/PL; без графиков полива, лечения и неподтверждённых обещаний безопасности |
| Полив (`watering`) | Интервалы полива по сезонам (`spring`/`summer`/`fall`/`winter` в днях), метод полива и предпочтение к дренажу из Plantfolio с явным уровнем сопоставления (`species_exact` / `species_synonym` / `genus_representative` / `botanical_group_representative`) для всех 606 видов каталога |

Несколько изображений и галерея вида — последующее расширение, не условие первого этапа.
Латинские синонимы можно сохранить для поиска, но они не заменяют распространённые названия.
Описание Wikidata не считается автоматически готовым общим описанием: имеющиеся тексты
нужно проверить на пригодность для карточки и дополнить при необходимости.

## Вид и экземпляр пользователя

Каталог описывает вид. Растение в коллекции — отдельный экземпляр со ссылкой на вид.
При добавлении по фото главным изображением экземпляра в коллекции и его карточке
становится загруженное пользователем фото. Оно не заменяет общее изображение вида
и не публикуется в каталоге. При добавлении из каталога используется изображение вида.

Фото → определение вида → подтверждение или исправление пользователем → сохранение
экземпляра с исходным фото. Если вид определить не удалось, доступны повтор и ручной
выбор в каталоге; исходное фото сохраняется в черновике. До подтверждения нельзя
показывать описание предполагаемого вида как установленный факт.

Для этого этапа добавление не требует вопросов об уходе, готового care profile,
диагноза или готового расписания. Действует текущий лимит добавления: четвёртое растение
на Free требует подписку. Определение только вида не диагностирует болезнь; основная
диагностика может определить вид в том же вызове. Правила приватности и квоты сохраняются.

## Подготовка данных и архитектура

- Сохранить существующий выпуск из 606 видов и исправить его реальные редакционные пробелы.
  Нового обязательного минимума видов нет. Затем подключение
  полученного каталога к приложению; существующий пилот сохраняется как история.
- Выбирать источники под эти поля. Не искать поставщика полной карточки ухода для
  завершения базового каталога. Сохранять происхождение текста/названий и права на фото.
- Данные каталога обслуживает наша база/Storage и локальный кеш; внешние источники
  используются при подготовке данных.
- Базовый каталог уже проверен локально без релиза KB (T147). Для рекомендаций применять правила публикации по каждому действию.
- Факты ухода и протоколы болезней подключаются по стабильным ID и проверяются отдельно.
  Отсутствующий профиль не скрывает растение из каталога и не заполняется заглушкой.

## Приёмка первого этапа

1. На EN и PL отображается список 606 видов: научное/доступное обиходное
   название и главное фото. Поиск находит вид по научному и каждому сохранённому названию.
2. Карточка показывает научное имя, распространённые названия, фото и общее описание.
3. Добавление из каталога сохраняет экземпляр без профиля ухода; он остаётся после
   перезапуска приложения. Недоступные модули не показывают фиктивные рекомендации.
4. Добавление по фото сохраняет подтверждённый вид и именно пользовательское фото;
   проверены исправление вида, ошибка распознавания, повтор и изоляция личных фото.
5. Тот же сценарий работает при отсутствии опубликованной KB ухода/болезней.
   Проверки на fixtures и настоящие API/Storage/устройство фиксируются отдельно.

Приёмка в приложении ещё не выполнена. Статус массовой выгрузки фиксируется отдельно
в `catalogue/releases/skeleton-300-v1/coverage.json` и handoff. Задачи: T147–T151 в
