# Narat — собственная база растений: источники и импорт

> Исследовательский материал; расширенные поля и источники не задают обязательный scope. С 9 ноября 2026 действует [минимальная подготовка карточек](../specs/001-plants-ios-mvp/knowledge-base-pipeline.md); нет обязательного полного профиля или универсального pipeline.

## Актуальный приоритет — 2026-11-04

Сначала [базовый каталог](plant-catalogue-skeleton.md): научное имя, распространённые
названия, одно фото и общее описание. Сразу массово выгружаются 300 разных видов. Отдельного этапа
доведения трёх пилотных карточек нет. Для текущей выгрузки выбрана связка Wikidata
(имена/ID), Wikipedia EN/PL (описания), Commons (фото с проверкой каждого файла). Полные профили ухода и болезней — отдельные следующие этапы;
прежние указания ниже «сначала полный профиль монстеры» сохраняются как история
и больше не определяют ближайший шаг. Источники ухода не блокируют базовую карточку.


Дата проверки: 2026-11-02. Цель — собственные данные для согласованных 300 видов MVP и связанных профилей проблем. Внешние API/сайты используются при подготовке и обновлении релиза; приложение обращается к нашему PostgreSQL/Storage и локальному кешу. Прямые ссылки на чужие фотографии не используются как основной источник изображения в приложении.

## Источники по типам данных

| Данные | Выбранный путь | Состояние |
|---|---|---|
| Латинские имена, синонимы, таксономия | Версионная выгрузка WCVP/Kew; Wikidata для внешних ID, EN/PL labels/aliases; GBIF как дополнительная сверка | Wikidata structured JSON допущен по CC0; конкретный WCVP/GBIF release проверяется отдельно |
| Названия EN/PL | Wikidata + редакционная проверка; исходная латиница сохраняется | Отсутствующий перевод не выдумывается; label не автоматически считается общеупотребительным названием |
| Фотографии | Wikimedia Commons с проверкой лицензии каждого файла; при необходимости собственная/заказанная съёмка | API imageinfo/extmetadata → проверка → скачивание бинарного файла в наш Storage; автор/лицензия/изменения сохраняются |
| Свет, полив, субстрат, влажность и прочий уход | Разрешённые материалы NC State/Extension и других согласованных доноров; собственный структурированный профиль на их основе | Права на автоматический сбор, хранение, перевод и offline synthesis ещё требуют проверки по каждому источнику |
| Кошки/собаки | Разрешённый источник с точной привязкой к виду | ASPCA включён для личной некоммерческой сверки; автоматический импорт/публикация требуют отдельного основания |
| Симптомы/первая помощь/восстановление | Отдельные ConditionProfile из согласованных независимых материалов и предметных проверок | Не заменяются фотографиями/названиями из Wikidata; нужна отдельная цепочка из KB-модуля |

WCVP/Wikidata/GBIF, переиспользующие одну исходную запись, не считаются тремя независимыми подтверждениями ухода. Для публикации действия нужны проверенные происхождение, права и применимость; обязательного числа доноров нет. Таксономический пилот сам по себе не подтверждает пригодность совета по уходу.

## Что установлено по условиям

- [Wikidata Licensing](https://www.wikidata.org/wiki/Wikidata:Licensing): структурированные данные основных пространств — CC0. Это разрешение не переносится на связанные статьи и картинки. Доступ — по [официальной политике](https://www.wikidata.org/wiki/Wikidata:Data_access), с осмысленным User-Agent/контактом и соблюдением лимитов.
- [Kew Cite Us](https://powo.science.kew.org/cite-us) и [About WCVP](https://powo.science.kew.org/about-wcvp): taxonomy dataset имеет собственную версию/цитирование. Перед импортом выбираем точную выгрузку и сохраняем её README/license/checksum. Не распространяем лицензию таксономии на всё содержимое POWO. Автоматический запрос `/about` в этой проверке возвращал 403; обход не выполнялся.
- [GBIF archive](https://hosted-datasets.gbif.org/datasets/backbone/README.html): доступны Darwin Core/табличные выгрузки. Разрешения проверяются для конкретного набора; прежнее общее `CC0` в нашем списке не подтверждалось.
- [Commons reuse](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia): условия зависят от конкретного файла. Для первого набора выбираем Public Domain/CC0/CC BY; CC BY-SA можно подключать при выполнении условий для производных изображений. NC/ND/неизвестные права не допускаем в коммерческий автоматический поток.
- [Perenual Terms](https://perenual.com/terms-of-service), License: публичные website terms ограничивают коммерческое использование, дублирование и автоматический сбор. [API](https://perenual.com/docs/api) технически выдаёт нужные поля, но сам доступ к API не подтверждает право постоянного зеркала. Для ручного некоммерческого референса источник включён. Автоматическое получение/хранение через API проверяется по применимым API-условиям отдельно; назначение «некоммерческий» само по себе не снимает ограничения на extraction.
- [ASPCA Legal Information](https://www.aspca.org/about-us/legal-information): указанное разрешение копирования относится к личному некоммерческому использованию. Источник включён для личного некоммерческого референса; индивидуальная копия должна сохранять уведомления. Это не blanket permission на автоматическую выгрузку и преобразование всей базы.
- [NC State об изображениях](https://extensiongardener.ces.ncsu.edu/news/get-the-picture-with-the-plant-toolbox/): фото имеют отдельные CC-лицензии, в том числе NC; их проверяем поштучно. Это не blanket permission на текст/весь сайт.
- [Open Plant Data FAQ](https://www.openplantdata.com/faq): обычная подписка требует убрать фото после окончания доступа; это не выбранное основание для постоянной автономной фотобазы. Индивидуальный договор возможен, но его условия здесь не подтверждены.

Это фиксация прочитанных условий для проектного отбора, не согласование всех доноров. Не используются обход блокировок, чужие cookies или переработка запрещённого контента через LLM. Неопределённые операции остаются закрытыми, пока не появится явное основание.

## Некоммерческие референсы — уточнение владельца 2026-11-02

Perenual и ASPCA включены как источники примеров и ручной сверки для личного некоммерческого прототипа. В реестре у них `usage_context=personal_noncommercial_reference` и разрешена операция `manual_reference`. У ASPCA дополнительно отражено разрешение одной личной копии с сохранением уведомлений по прочитанным условиям.

Их материалы не получают автоматический статус готового приложения/KB. Общий ingestion gate продолжает требовать отдельного разрешения каждой операции: автоматического получения, хранения raw, обработки LLM и публикации. Сборщик Wikidata не расширяется до этих сайтов через один флаг `status=allowed`. Уточнение относится к текущим референсам; рыночная спецификация платного MVP и лицензии выпущенных записей этим не изменены.

## Как получаем и храним

1. **Seed:** фиксируем 300 конкретных видов и доказательства соответствия рынку PL. Внутренний `plant_id` устойчив; источник имеет отдельный ID/revision. Сорта не считаем отдельными видами ради количества.
2. **Сбор:** официальная выгрузка/API предпочтительнее HTML. Для 300 видов возможен пакет запросов; для большого таксономического корпуса — готовый dump. HTML-парсер пишем для разрешённого источника с ограничением частоты, кешем и остановкой на 403/429.
3. **Raw:** разрешённый исходный JSON/CSV/Markdown, URL, дата, версия, sha256 и снимок прав. Этот слой нужен для воспроизводимости; закрытый или лишний контент не копируем под формулировкой «вся информация».
4. **Нормализация:** имена/синонимы/единицы/языки → структурированные записи. Несовпадение вида/ранга, конфликт фактов, отсутствие лицензии или источников → карантин. Unknown не превращается в safe, а интервалы ухода не выводятся из среднего по нескольким сайтам.
5. **Уход:** offline synthesis только из разрешённых документов → схемы и предметные guardrails → редакционный отчёт. LLM не является первоисточником и не создаёт недостающие факты.
6. **Медиа:** скачиваем разрешённые файлы и свои производные размеры в наш Storage, сохраняя автора, страницу источника, точную лицензию и сведения об изменениях. URL донора остаётся атрибуцией, не runtime-зависимостью.
7. **Выпуск:** атомарный versioned release → PostgreSQL/Storage → API приложения. Последующие обновления запускаются нами отдельно и явно; прежняя рабочая версия остаётся доступной при ошибке обновления.

Схема уже предусматривает `source_registry`, `source_documents`, `catalogue_taxa`, `taxon_external_ids`, `taxon_names`, `catalogue_media`, `care_profiles` и KB releases. SQLite ниже — локальный staging для разработки без готового Supabase; production-импорт и публикация ещё не реализованы.

## Что создано сейчас

- `knowledge-base/manifests/source-registry.json`: operation-level разрешения/ограничения и ссылки на прочитанные условия. Wikidata structured data допускается к пакетному импорту; Perenual/ASPCA включены для личного некоммерческого референса, с отдельными operation-level ограничениями; media/care — отдельные проверки.
- `knowledge-base/pipeline/rights.py`: запрещает candidate/blocked/expired, операции без разрешения и просроченную проверку. Дата повторной проверки — наша внутренняя политика, не утверждение, что лицензия истекает в эту дату.
- `knowledge-base/pipeline/import_wikidata.py`: последовательная загрузка entity JSON, кеш/sha256/provenance, проверка scientific name/rank, идемпотентная запись draft в SQLite и журнал импорта с копией реестра прав. Нет runtime-вызова из приложения и автоматической публикации.
- `knowledge-base/manifests/pilot-seed.json`: 3 пары научное имя/QID, проверенные по страницам Wikidata — Monstera deliciosa, Ficus elastica, Epipremnum aureum. Это пилот, не готовый seed 300 видов.
- `knowledge-base/tests/test_catalogue_import.py`: 7 offline-тестов прошли. Проверены запрет неразрешённых операций, несовпадение вида/ранга, checksum, отсутствие выдуманного ухода/safety, сохранность базы при ошибке и повтор без дублей.
- В `catalogue/manifests/sources.json` сняты прежние неподтверждённые `approved=true`; добавлена ссылка на operation-level registry. Успешная валидация bundle старым `catalogue/import.ts` ещё не означает доказанные права: интеграция нового rights gate с publish — следующая работа.

**Статус фактических данных (обновлено):** пилот реально загружен: 3 полных Wikidata entity JSON и 3 Commons originals, локальная SQLite-база и JSON/CSV. Прямой HTTP-импорт с предоставленным владельцем контактом и повторная offline-сборка прошли. Сохранена одна личная ASPCA reference-страница; Perenual не выгружался. Уход/токсичность и полный seed 300 пока не готовы. Подробности — [отчёт пилота](validation/plant-data-pilot-2026-11-02.md).

### Порядок получения

1. Для выбранного донора уточнить доступные export/API/HTML и разрешённые операции. NC State/RHS/Wisconsin/UC IPM пока кандидаты на ingestion; видимость страницы не приравнивается к разрешению зеркала. Perenual остаётся дополнительным ручным референсом, импорт его API не включён.
2. Разрешённые raw-материалы загружать заранее, сохранять URL/версию/дату/хеш и field evidence; не получать их во время работы пользователя.
3. Собрать один Monstera PlantProfile, разобрать противоречия и проверить схему/семантику. Правило минимум трёх независимых доноров не заменяет проверку каждого утверждения.
4. Повторить для двух остальных; сохранить EN/PL и связанные протоколы в своей SQLite/PostgreSQL. Данные/переводы с неподтверждённым основанием не получают published.

В этом этапе проверена доступность и релевантность источников, подготовлен маршрут. Новые care/safety-факты в пилот не импортировались, источники автоматически не допускались, код/тесты не менялись. Проверка условий для хранения/перевода/LLM по каждому новому донору остаётся следующим шагом; если нужных разрешений нет, используем согласованный лицензированный набор или собственные материалы специалиста.
